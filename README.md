## 🧠 Why Neuron?

**Cognitive Multi-Agent Architecture for Complex AI Systems**

Neuron is a research framework exploring cognitive architectures through modular multi-agent coordination. Built on neuroscience-inspired principles, it provides sophisticated agent coordination patterns and memory systems for developing resilient AI applications.

🔬 **Current Status: Advanced Research Platform** - Production-ready architecture with agent behavior modeling. Suitable for research, prototyping, and foundational development of cognitive AI systems.

Neuron excels in scenarios traditional AI struggles with:

- **🔄 Resilient Processing**: Handles ambiguous inputs, contradictory information, and incomplete data without system failure
- **🧠 Persistent Memory**: Maintains context across extended interactions for longitudinal reasoning
- **⚡ Selective Activation**: Dynamically combines only needed capabilities rather than running every component
- **🔀 Parallel Coordination**: Processes multiple tasks simultaneously while maintaining consistency
- **👁️ Complete Observability**: Every decision is traceable with full reasoning paths and evidence trails

### 🏈 Production Implementation: Fantasy Football Neuron

Currently live and serving **325+ content creators** during NFL primetime, this implementation demonstrates Neuron's capacity for high-velocity, stateful agent coordination.

* **Codebase:** See the [`FFSapp`](./FFSapp) and [`FS_Neuron`](./FS_Neuron) and other private directories.
* **Scale:** Orchestrates **1,500+ concurrent agents** with **99.9% uptime**.

### Your First Agent Circuit

A circuit is a set of agents joined by connections. Input goes to the INPUT
agents; each agent's reply travels along its connections to the next agents;
replies from OUTPUT agents come back from `get_output()`. This example is
[`examples/quickstart.py`](examples/quickstart.py) and runs as part of the
test suite:

```python
import asyncio

from neuron import BaseAgent, CircuitDefinition, initialize


class Intake(BaseAgent):
    """Tags a support message with positive and negative signals."""

    def _initialize(self):
        pass

    async def process_message(self, message):
        text = message.content["message"].lower()
        signals = {
            "positive": any(word in text for word in ("love", "great", "thanks")),
            "negative": any(word in text for word in ("broken", "refund", "angry")),
        }
        await self.send_message(message.sender, {**message.content, "signals": signals})


class ContradictionCheck(BaseAgent):
    """Flags messages that are positive and negative at the same time."""

    def _initialize(self):
        pass

    async def process_message(self, message):
        signals = message.content["signals"]
        mixed = signals["positive"] and signals["negative"]
        await self.send_message(
            message.sender, {**message.content, "contradiction": mixed}
        )


class Responder(BaseAgent):
    """Writes the reply."""

    def _initialize(self):
        pass

    async def process_message(self, message):
        if message.content["contradiction"]:
            reply = "Sounds like you like it but it isn't working. Repair or refund?"
        else:
            reply = "Thanks, we're on it."
        await self.send_message(message.sender, {"reply": reply})


async def main():
    core = initialize()
    core.start()  # components run as tasks on this event loop
    for agent_type in (Intake, ContradictionCheck, Responder):
        core.agent_manager.register_agent_type(agent_type)

    circuit = CircuitDefinition.create(
        name="CustomerSupportCircuit",
        description="Detects mixed signals and asks a clarifying question",
        agents={
            "intake": {"type": "Intake", "role": "INPUT"},
            "checker": {"type": "ContradictionCheck", "role": "PROCESSOR"},
            "responder": {"type": "Responder", "role": "OUTPUT"},
        },
        connections=[
            {"source": "intake", "target": "checker", "connection_type": "direct"},
            {"source": "checker", "target": "responder", "connection_type": "direct"},
        ],
    )
    circuit_id = await core.circuit_designer.create_and_deploy(circuit)

    message = "I love this product but it's completely broken and I want a refund"
    await core.circuit_designer.send_input(circuit_id, {"message": message})
    output = await core.circuit_designer.get_output(circuit_id, timeout=5)
    print(f"{output['agent']}: {output['content']['reply']}")

    await core.circuit_designer.terminate_circuit(circuit_id)
    await core.shutdown_async()


if __name__ == "__main__":
    asyncio.run(main())
```

```bash
python examples/quickstart.py
# responder: Sounds like you like it but it isn't working. Repair or refund?
```

The framework is asynchronous: call `initialize()` and `core.start()` from
inside a coroutine, as above, and `await` the circuit methods. Connections can
be `direct`, `conditional` or `filtered` (a Python expression over `message`
in the connection's `metadata`), or `transformed` (an expression that rewrites
the content). Expressions are evaluated with `eval`, so only deploy circuit
definitions you trust.

## 🏗️ Core Agent Architecture

### Agents

Every agent subclasses `BaseAgent` and implements `process_message`; it
replies with `send_message`. The framework ships four built-in types:
`ReflexAgent` (rule-based, fast), `DeliberativeAgent` (multi-step
reasoning), `LearningAgent` (adapts from feedback) and `CoordinatorAgent`
(runs workflows across other agents). Register your own types and use them
by name in circuits, as in the [Quick Start](#your-first-agent-circuit).

```python
from neuron import ReflexAgent, create_agent

# inside a coroutine, after initialize() and core.start()
agent_id = create_agent(ReflexAgent, name="Intake", description="Classifies requests")
core.agent_manager.register_agent_type(MyAgent)   # a BaseAgent subclass
```

### Multi-Layered Memory

Five memory systems, inspired by human memory: `WORKING`, `EPISODIC`,
`SEMANTIC`, `PROCEDURAL` and `EMOTIONAL`.

```python
from neuron import MemoryType

memory = core.memory_manager

await memory.store(
    {"event": "customer_complaint", "resolution": "replacement_offered"},
    MemoryType.EPISODIC,
    importance=0.8,
    metadata={"customer_id": "12345"},
)

history = await memory.query(
    {"metadata.customer_id": "12345"}, memory_type=MemoryType.EPISODIC
)
```

### SynapticBus Communication

Agents exchange `Message`s over the SynapticBus. Inside a circuit, an agent
replies to whoever sent it a message and the circuit forwards the reply
along its connections. Outside a circuit, address agents directly:

```python
from neuron import Message

await core.synaptic_bus.send(Message.create(
    sender="intake_agent",
    recipients=[reasoning_agent_id],
    content={"type": "customer_issue", "sentiment": "mixed"},
    metadata={"priority": "high"},
))
```

### Circuits and Connections

A circuit wires agents together. Each connection has a type:

| Type | Behaviour |
|------|-----------|
| `direct`, `weighted` | Forward every message |
| `conditional`, `filtered` | Forward when a Python expression over `message` is true (`metadata.condition_code` / `metadata.filter_condition`) |
| `transformed` | Rewrite the content first (`metadata.transform_code`) |

```python
{"source": "intake", "target": "escalation", "connection_type": "conditional",
 "metadata": {"condition_code": "message.content['urgency'] == 'high'"}}
```

Built-in templates (`sequential_pipeline`, `star_network`) are listed by
`neuron circuit list`. Expressions are evaluated with `eval`; only deploy
circuit definitions you trust.

### Command Line

```bash
neuron --help
neuron agent list      # available agent types
neuron circuit list    # circuit templates
neuron start           # run the framework until Ctrl+C
```

Each command runs in its own process, so state (such as a deployed
circuit) does not carry over from one command to the next; use the Python
API for anything stateful.

## 🌟 Why Choose Neuron's Agent Architecture?

### **vs. LangChain**
- **Memory**: Persistent multi-layered **agent memory** vs. token-level context
- **Reasoning**: Parallel **multi-agent coordination** vs. sequential chains  
- **Observability**: Full **agent decision traces** vs. execution logs only
- **Adaptability**: Dynamic **agent reconfiguration** vs. manual flow updates

### **vs. Direct API Calls**
- **State Management**: Rich **agent memory systems** vs. stateless calls
- **Error Handling**: Graceful **agent degradation** vs. hard failures
- **Coordination**: **Multi-agent orchestration** vs. single-shot responses
- **Explainability**: Complete **agent reasoning traces** vs. black box outputs

### **vs. AutoGen/CrewAI**
- **Brain-Inspired Design**: Neuroscience-based **agent principles** vs. generic multi-agent
- **Memory Architecture**: Sophisticated **agent persistence** vs. simple conversation history
- **Fault Tolerance**: Component-level **agent resilience** vs. system-wide failures
- **Observability**: Deep **agent introspection** vs. basic logging
